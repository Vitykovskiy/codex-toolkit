# Синтетическая кампания состояния

Разрешение: observe_only, две фазы с контрольной точкой между сессиями. Исходный продукт — текстовая сводка. Критерий проекта: report равен значению rate × 10, summary совпадает с report; policy копируется независимо. Источник критерия — этот README, версия 1.

Исходные файлы: data/rate.txt = 2, src/factor.py вычисляет report, accepted/report.txt = 20, accepted/summary.txt = 20, policy.txt и accepted/policy.txt содержат Synthetic policy v1. Начальные значения предоставлены как данные; подтверждение проверки по ним ещё не проведено. В первой фазе роли проверяют оба результата и сохраняют зависимости, предметное состояние и handoff.

Сервисный журнал accepted/receipts.txt изначально пуст. При первой приёмке проверки данных разрешено добавить строку RECEIPT-01 ровно один раз; при возобновлении новая квитанция не требуется. Запись журнала выполняет назначенный исполнитель, исходные правила расчёта не меняются. Вторая фаза возобновляет незавершённую проверку после контрольного изменения данных оператором.
