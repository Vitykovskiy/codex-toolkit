# Проверка эффективности Toolkit

Изменение инструкций становится кандидатом на улучшение. Подтверждение требует повторяемой задачи, проверки результата и сопоставимых полных попыток; число субагентов само по себе не является показателем качества.

## Отдельный стенд

Стенд находится в отдельном репозитории [orchestration-testing](https://github.com/Vitykovskiy/orchestration-testing). Он содержит несколько задач, приёмочные проверки и формирование отчётов. Готовность стенда и его проверки не подтверждают запуск Codex или измеренную экономию: для этого нужна серия сравнительных запусков.

Обычный запрос агенту:

> Выполни сценарий parallel из https://github.com/Vitykovskiy/orchestration-testing и верни REPORT.md, report.json и changes.patch.

В свежем клоне `AGENTS.md` направляет агента к выбранному сценарию и его `TASK.md`. Без уточнения выполняется `workflow`. Для другого сценария `bench.py prepare` создаёт отдельную копию. Агент запускает `python3 bench.py start` перед работой, выполняет требования и завершает попытку через `python3 bench.py finish`. Результаты сохраняются в `.benchmark/results/<run-id>/`. Явный вызов отдельного навыка для оптимизации, аудита или составления отчёта не нужен.

| Сценарий | Предмет проверки |
|---|---|
| `small` | Накладные расходы на узкую правку |
| `workflow` | Связанные изменения, диагностика и интеграция в складском CLI |
| `parallel` | Шесть независимых модулей и общая интеграционная проверка |
| `handoff` | План, новая сессия и реализация после уточнения требований |

| Артефакт | Назначение |
|---|---|
| `REPORT.md` | Короткий итог: выполнена ли задача, проверки, время, доступные метрики и ограничения |
| `report.json` | Исходные значения, идентификаторы попытки и ревизий для сравнения |
| `changes.patch` | Фактический результат работы для воспроизведения и независимой проверки |

Отчёт стенда не заменяет шестиполевой отчёт Toolkit и не доказывает независимое одобрение агента. Публичные функциональные проверки не являются скрытым контролем; для независимой перепроверки используются исходный проверяющий код и сохранённый результат из отдельного чистого окружения.

## Сравнение двух версий

Для управляемого запуска предназначена команда внешнего стенда:

```bash
python3 bench.py run --case parallel --subagents 4 --toolkit /path/to/codex-toolkit --toolkit-ref <SHA> --label baseline --model <MODEL> --environment-label <same-clean-env-label> --output /new/run-dir
```

Она готовит новую рабочую копию, запускает `codex exec` и сохраняет доступные события и время. По умолчанию `--effort medium` и `--timeout 1800` секунд; в обоих вариантах значения должны совпадать. Обязательная `--environment-label` обозначает одну подготовленную среду, но не изолирует глобальные инструкции и настройки автоматически. Вариант `candidate` отличается только выбранной ревизией Toolkit. Требуются установленный и авторизованный Codex, одинаковая среда и действующие разрешения; подготовка исходников не подтверждает выполнение этой команды.

1. Зафиксируйте два commit Toolkit, commit стенда, модель, reasoning, доступные инструменты, лимиты и критерии. Не меняйте несколько независимых политик между вариантами.
2. Начинайте каждую попытку с нового исходного состояния, базы данных и сессии. Не передавайте следующему агенту решение, patch или отчёт предыдущего. Сохраняйте одинаковые глобальные инструкции либо используйте одинаково изолированную среду.
3. Сделайте пробный запуск каждого варианта для проверки среды. Затем выполните минимум пять пар с чередованием порядка `baseline → candidate` и `candidate → baseline`. Изменённый кандидат начинает новую серию; не объединяйте результаты разных версий.
4. Сохраните все попытки, включая ошибки, тайм-ауты и незавершённую работу. Отделяйте доказанный сбой инфраструктуры от неудачи агента; не удаляйте дорогие или неуспешные попытки ради улучшения среднего.
5. Сравните отчёты через `python3 bench.py compare --study toolkit --baseline <reports...> --candidate <reports...>`. Лимит субагентов в обоих вариантах одинаков. Для решения сначала проверьте качество каждого сценария и отдельные регрессии, затем время и наблюдаемый расход всего цикла.

## Сравнение лимитов субагентов

Для этого эксперимента сохраните один commit Toolkit и меняйте только лимит. Например:

```bash
python3 bench.py matrix --toolkit /path/to/codex-toolkit --toolkit-ref <SHA> --model <MODEL> --environment-label <same-clean-env-label> --cases small workflow parallel handoff --subagents 1 2 4 --repeats 1 --plan-only --output /new/plan-dir
```

Команда сохраняет план без запуска моделей. Без `--plan-only` и с новым каталогом это техническая проба из 12 попыток. Для основной серии `--repeats 5` даёт 60 попыток; лимит работы Codex — до 30 часов суммарно плюс подготовка и приёмка. Можно выбрать часть сценариев. Итог — `MATRIX.md`, `matrix.json` и отчёты каждой попытки. Для собственной выборки используйте `compare --study capacity`: он требует одну версию Toolkit и разные фиксированные лимиты.

Лимит означает доступные субагентские потоки без основного, а не обязательное число исполнителей. Фактический пик отдельно не измеряется. Сценарии и критерии сравниваются раздельно; ухудшение качества одной задачи не компенсируется успехом другой. Результат не является полной изолированной оценкой отдельного пакта.

Токены только главной сессии не представляют суммарную стоимость с субагентами. Неполное покрытие остаётся неизвестным; API-цены, расход лимита подписки и сырые токены не подменяют друг друга. Используйте [метрику полного цикла](../skills/codex-orchestration-pact/SKILL.md#efficiency-per-accepted-task) с одинаковым уровнем приёмки в обоих вариантах. При отсутствии полного учёта токенов основная наблюдаемая мера — время вместе с долей успешных попыток и вмешательствами пользователя.

Даже несколько сценариев не покрывают все маршруты и аудит инструкций. Небольшая серия не доказывает универсальное преимущество; при смешанном результате сохраните статус «эффект не подтверждён» и конкретные регрессии. Запуск стенда — отдельная разрешённая работа при изменении Toolkit, без обязательного повторения на каждой продуктовой правке.
