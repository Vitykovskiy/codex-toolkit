# Project-local подключение

Это процедура отдельного будущего запуска в проекте-потребителе. Доработка toolkit ничего не устанавливает в продуктах или глобальных каталогах. Канонические источники toolkit изменяются при разработке, импортированный upstream-снимок в продукте сохраняется неизменным.

## Проверенный источник

Выберите repository и точный commit, зафиксируйте дату и основание выбора. Получите отдельный временный clone с detached checkout нужного SHA либо git archive точного commit в новый временный каталог; исходный рабочий checkout и его индекс не меняйте. Подтвердите исходную ревизию по Git blobs/manifest источника. Для незакоммиченного target сохраните явный manifest разрешённых исходников, включая новые файлы. Исключите .git, окружения, runtime, старые трассы и чужие untracked. Не очищайте дерево пользователя.

Прочитайте согласованность зависимостей и прав. Недоступную или исключённую существующую проверку сохраните с причиной и result: null. Новые проверочные средства регулирует [общее правило](../skills/codex-orchestration-pact/SKILL.md#general-rule-for-verification-means).

## Preflight потребителя до записи

Установите фактический корень проекта, ветку/detached, HEAD, staged/unstaged/untracked и отпечаток индекса. Для .agents, .agents/skills, .codex, .codex/agents и каждого затрагиваемого потомка проверьте тип через lstat, цепочку родителей, реальную цель symlink/reparse point/junction, существующий Git-корень и worktree. Для отсутствующего пути проверяйте ближайшего существующего родителя.

Составьте перечень существующих файлов, одноимённых скиллов, профилей, expressa-* расширений и конфигурации. Отделите несвязанные файлы и локальные изменения. Небезопасная цель, петля ссылки, внешний Git/worktree или конфликт существующего файла останавливают запись в затронутую область до разрешения. Не снимайте ссылки автоматически и не используйте рекурсивное удаление.

## Комплект и зависимости

Полный комплект содержит 11 скиллов и 13 профилей из [каталога](../README.md). Выборочный импорт замыкается транзитивно по обязательным и применимым условным зависимостям.

| Процедура/профиль | Необходимый локальный источник |
|---|---|
| long-orchestration | orchestration-pact |
| product-quality | long-orchestration, orchestration-pact, UI-analysis-pact, web-verification |
| UI-analysis при документировании | documentation-pact |
| web-implementation | development-pact |
| debugging при исправлении | development-pact |
| любой профиль | канонический report в orchestration-pact; в dispatcher также long-orchestration |

Не копируйте отдельный SKILL без его references, metadata, templates и нужных соседних каталогов. После preflight скопируйте выбранные каталоги skills/<имя>/ в .agents/skills/<имя>/, профили agents/*.toml — в .codex/agents/. Перед заменой существующего импорта сверяйте его прежний manifest и локальные изменения; не перезаписывайте их без разрешённого решения. Каждый файл импортированного скилла должен совпасть по байтам со снимком. Проектные расширения размещаются отдельно от upstream.

Канонические профили содержат ссылки ../skills/…, рассчитанные от agents/ toolkit. В проектных копиях замените только этот префикс на ../../.agents/skills/…, рассчитанный от .codex/agents/; проверьте разрешение каждой Markdown-цели, существование и принадлежность проекту. Сохраните исходные профили в снимке, а diff проектной адаптации перечислите отдельно. Модельные поля не добавляются автоматически.

## Происхождение и runtime

Создайте следующие долговременные файлы:

- .agents/SOURCE.md: repository, версия из [CHANGELOG](../CHANGELOG.md), точный commit, дата импорта, вид снимка, импортированный комплект, список файлов, фактические проверки и неизвестности. Для незакоммиченного target укажите исходный commit и идентификатор/manifest снимка; номер не заменяет точное происхождение.
- .agents/upstream.sha256: SHA-256 каждого импортированного исходного файла с путём относительно корня toolkit. Для адаптированных профилей хеш upstream сохраняется до адаптации.
- .agents/LOCAL-ADAPTATIONS.md: адаптированные профили и пути, причина, источник разрешения, SHA-256 результата и ссылки на проектные правила. Сами правила здесь не дублируются.

Исходные skill-копии, профили, SOURCE/manifest и долговременные правила должны отслеживаться проектом. Добавление в индекс/commit выполняется только при соответствующем разрешении; до него честный статус — «подготовлено, ещё не tracked». Игнорируйте .codex/tmp/ и выбранные runtime-каталоги, не весь .codex/.agents и не произвольный state.yaml: шаблоны внутри references/templates — исходники. Не переносите в приложение отчёты и документацию разработки toolkit как runtime-зависимости.
