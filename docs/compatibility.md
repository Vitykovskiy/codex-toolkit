# Совместимость и подключение

Совместимость оценивается по отдельным уровням: корректный файл, документированное обнаружение, фактическая загрузка и поведение. Положительный результат одного уровня не подтверждает остальные. Дата локальной проверки и чтения руководств: 2026-09-05.

## Форматы исходников

Скилл содержит Markdown с YAML frontmatter (`name`, `description`); `agents/openai.yaml` задаёт метаданные интерфейса и политику выбора. Toolkit задаёт `allow_implicit_invocation: false` для коммуникации и `true` для остальных восьми скиллов. Прямое подключение коммуникации в корневом `AGENTS.md` остаётся отдельной проектной инструкцией. Формат и значение политики документированы в [Build skills](https://learn.chatgpt.com/docs/build-skills).

Профили `agents/*.toml` содержат `name`, `description`, `developer_instructions` и `sandbox_mode`; модель и reasoning в профилях toolkit отсутствуют. Точное имя интеграционного проверяющего — `integration_reviewer`, файл — `integration-reviewer.toml`. Формат standalone-профилей описан в [Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Python 3.11+ и зависимости разработки нужны локальному validator, а не исполнению Markdown клиентом. Структурный разбор не доказывает, что клиент применил поле или обеспечил изоляцию.

## Документированное обнаружение

В [руководстве навыков](https://learn.chatgpt.com/docs/build-skills) прочитан раздел Where Codex loads local skills: проектный каталог `.agents/skills` ищется от рабочего каталога до корня репозитория; пользовательский — `$HOME/.agents/skills`. Там же документировано следование symbolic links для каталогов навыков. Каталоги toolkit `skills/` и `agents/` сами по себе регистрацию не выполняют.

[Руководство подагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents) описывает standalone TOML в `$HOME/.codex/agents` и проектном `.codex/agents`. Параметры модели разрешаются отдельно; руководство описывает приоритет файла профиля и наследование отсутствующих настроек. Это документированное поведение, не результат локального запуска профилей toolkit. Реальное применение sandbox и runtime overrides требует проверки конкретной сессии.

[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) описывает сбор глобальных и проектных инструкций при старте, от корня к рабочему каталогу. Инструкция toolkit не должна подменять соглашения проекта-потребителя.

## Варианты подключения

Каноническими остаются `skills/` и `agents/`. Для локального проекта можно разместить выбранные каталоги навыков в `.agents/skills`, а выбранные TOML-профили — в `.codex/agents`; копии потребуется синхронизировать с источником. Для навыков документирован вариант symbolic link на канонический каталог. Его создание зависит от ОС и разрешений. Поддержка ссылок на профили отдельно здесь не проверена.

Windows directory junction остаётся возможным способом уже существующего подключения каталогов. Переносимый вариант — явное размещение выбранных файлов в документированных каталогах; на macOS/Linux для навыков также применим документированный symlink. Эти варианты описаны без изменения пользовательской установки. Перед подключением сохраните действующую регистрацию и проверьте справку применимого клиента. Сведения старой конфигурации и Codex `0.144.4` не являются проверкой текущей среды; старый пользовательский `config.toml` автоматически не удаляется и не переписывается.

## Фактически проверенная среда

| Проверка | Наблюдение | Граница доказательства |
|---|---|---|
| `codex --version` | `codex-cli 0.152.0`, exit 0 | Версия доступного CLI |
| `sw_vers`, `uname -m` | macOS 26.6.2, build 25G83, arm64, exit 0 | ОС и архитектура этой проверки |
| `codex --help`, `codex exec --help` | exit 0; описаны `exec --json`, `--ephemeral`, `--ignore-user-config`, `--sandbox`, `--cd`, `--add-dir` | Наличие параметров в локальной справке |
| Предупреждение CLI | Не удалось создать PATH aliases: `Operation not permitted` | Справка и версия всё же завершились успешно |

`--ignore-user-config` по справке отключает загрузку пользовательского `config.toml`; это не обещание отключить все глобальные навыки. В статье об evals встречается `--full-auto`, но текущая локальная справка его не перечисляет; команды статьи нельзя переносить без сверки.

## Результаты локальной приёмки

Структурная проверка прошла: 30 unit tests, validator — 0 errors / 0 warnings
(независимый отчёт `R-D01.md`, журналы `R-D01-fix-tests.log` и
`R-D01-fix-validator.log`). Проверки выполнены с Python 3.14.7 и PyYAML 6.0.3;
исполнение на минимальном Python 3.11 отдельно не проверено.

Загрузка в Codex имеет статус `unable_to_verify`. Единственная попытка target
W01 завершилась до событий модели: exit 1 за 0.159 секунды, пустой
`trace.jsonl`, итоговый ответ отсутствует. В stderr отдельно наблюдались
предупреждение readonly SQLite и ошибка инициализации in-process app-server
`Operation not permitted`; причинная связь между ними не установлена.
Попытка уже использовала `--ephemeral` и `--ignore-user-config`.

Диагностика подтвердила наличие настроек `sqlite_home` и `log_dir` в
установленном binary и официальном справочнике конфигурации. Это частичное
основание для переноса SQLite и логов на уровне процесса, а не проверенное
решение всей инициализации: полный перенос runtime-записей и устранение
ошибки app-server не подтверждены. Абсолютная невозможность запуска также
не доказана; повтор без новых доказательств не выполнялся.

Исходный baseline `f3f45cd9a068bb743367724fb4958858b10fcfb7` получен в отдельном
временном репозитории: все 33 файла независимо сверены с Git blobs и manifest,
HEAD точный, status чистый. Это проверка исходников, не загрузки клиента.
Сравнение с начальным HEAD описано в [карте миграции](refactoring-map.md).

Исторический target F01 содержал 89 файлов: 65 канонических на момент снимка
и 24 старых игнорируемых runtime-файла из `.codex/tmp/tasks/`. Равенство хешей
не подтверждает чистоту этого состава. По R-F01 consumer-проекты получали
только навыки; влияние дополнительных файлов на остановившийся до модели
W01 не установлено. После попытки исправлены четыре файла процедур и
справочников development/orchestration; независимый R-B02 подтвердил
исправления и повторные 30 tests / validator 0/0. Старые F01/F02 доказательства
не подтверждают текущие инструкции: актуальность снимков и будущая
поведенческая проверка имеют `needs_revalidation`. Подготовка и проверка
нового чистого target — отдельный шаг, его готовность здесь не утверждается.
Исторические артефакты сохраняются, число попыток остаётся 1/14.

## Непроверенные варианты

Фактическая загрузка девяти навыков и восьми профилей, исполнение
`allow_implicit_invocation`, полный routing, наследование модели/reasoning,
эффективные инструменты и sandbox, изоляция глобальных дублей, браузерные
действия, делегирование и возобновление остаются непроверенными. Запрошенные
CLI-настройки не доказывают их применение. Наличие или отсутствие браузера
для дочернего CLI не установлено. Windows, Linux, junction и иные версии
клиента здесь не проверялись.

Подготовлены 28 случаев; ни один не проверен поведенчески. После ошибки W01
восемь остальных target и пять baseline не запускались (`not_run`); расход —
1/14 попыток, получено 0 ответов модели. Сравнение эффективности —
`unable_to_verify`; время ошибки и размер каталога не являются метриками
скорости модели или загруженных инструкций. Счётчик токенов недоступен.

Источники этих результатов — временные отчёты `F00.md` / `R-F00.md`,
`F01.md` / `R-F01.md`, `F02.md` / `R-F02.md`, `runtime-diagnosis.md` и журналы
