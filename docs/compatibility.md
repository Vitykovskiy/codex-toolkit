# Совместимость и подключение

Корректный формат, документированное обнаружение, фактическая загрузка, поведение и эффективность — разные уровни доказательств. Текущая проверка руководств и CLI-справки датирована 2026-09-06; она не меняет даты исторических тестов.

## Форматы и документированное обнаружение

Скилл содержит Markdown с YAML frontmatter `name`/`description`; `agents/openai.yaml` задаёт интерфейсные метаданные и политику. В toolkit 11 скиллов: `allow_implicit_invocation: false` у communication и `true` у остальных десяти. Обязательность коммуникации здесь задаёт прямое правило [AGENTS](../AGENTS.md). Список доступных скиллов и чтение выбранной процедуры различаются. Формат и политика описаны в [Build skills](https://learn.chatgpt.com/docs/build-skills).

Руководство обнаружения описывает `.agents/skills` от рабочего каталога до корня Git, пользовательские и системные источники, а также следование symlink для скиллов. Одинаковые имена не сливаются. Поэтому project-local путь надо подтверждать фактически; наличие глобального дубля не подтверждает импорт. [Источник: Where Codex loads local skills](https://learn.chatgpt.com/docs/build-skills).

В toolkit 13 standalone TOML-профилей с `name`, `description`, `developer_instructions`, явными `model`, `model_reasoning_effort` и `sandbox_mode: workspace-write`. `reviewer-fast.toml` → `reviewer_fast` использует Terra/low только для буквальной несемантической проверки; остальные проверки поведения, смысла, безопасности или межчастевых связей используют обычный reviewer либо integration_reviewer. Astra-профили `analyst`, `architect_astra` и `quality_owner_astra` требуют дословного прямого применимого указания пользователя для конкретной роли и задачи. Файловое наличие профиля не даёт этого разрешения. Полная политика находится в [оркестрации](../skills/codex-orchestration-pact/references/complex-task-orchestration.md). Руководство описывает проектный `.codex/agents/` и пользовательский каталог профилей. Файловый формат не доказывает загрузку конкретного профиля. [Источник: Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Заданные в custom agent file `model`/`model_reasoning_effort` имеют приоритет. До применения файла клиент разрешает явный spawn, defaults `[agents]`, затем значения родителя; при выборе модели без effort действует уточнение руководства о default effort. Права также зависят от live runtime overrides родителя. Это документированное разрешение настроек, не наблюдение эффективной модели или sandbox текущего комплекта. [Источник: Custom agents; Approvals and sandbox controls](https://learn.chatgpt.com/docs/agent-configuration/subagents).

`workspace-write` нужен собственным отчётам; запрет предметной записи аналитикам/reviewer остаётся процедурным. Он не изолирует write-set технически. Python 3.11+/PyYAML нужны validator на отдельном снимке, не Markdown-runtime приложения.

## Подключение и параметры клиента

Канонические `skills/` и `agents/` сами ничего не регистрируют. Полная процедура копирования, транзитивные зависимости и адаптация ссылок профилей — в [project-local](project-local.md). Документированная поддержка skill symlink не доказывает поддержку ссылок на профили. Windows junction сохраняется как исторически возможный вариант, без текущей проверки на Windows. Существующая установка и старая пользовательская регистрация автоматически не изменяются.

2026-09-06 локально выполнены только `codex --version` и `codex exec --help` (оба exit 0): `codex-cli 0.152.0`. Справка содержит `--json`, `--cd`, `--sandbox`, `--ephemeral`, `--ignore-user-config`, `--model`, `--output-last-message`. Предупреждение о невозможности создать PATH aliases не помешало справке; оно не является установленной причиной будущего сбоя модели.

По этой справке `--ignore-user-config` отключает пользовательский config; это не доказательство отключения всех глобальных skills. `--full-auto` из [статьи eval-skills](https://developers.openai.com/blog/eval-skills) в текущей справке отсутствует. Флаги статьи не переносятся автоматически. Проверка версии/справки не запускает модель и не подтверждает доступность ID. Перед применением другого зависящего от версии параметра перечитайте соответствующий официальный раздел и локальную справку.

## Статусы доказательств

| Уровень | Что подтверждает | Текущее ограничение |
|---|---|---|
| Исходники/структура | Локальные tests, validator, ссылки и manifest конкретного снимка | Итоговые результаты сохраняет отчёт приёмки этого снимка; один parser не проверяет смысл |
| Смысловая приёмка | Независимое чтение ролей, зависимостей и прав | Не тождественна запуску клиента |
| Документация и CLI help | Перечисленные разделы прочитаны 2026-09-06, версия/справка доступны | Не подтверждают применение настроек |
| Загрузка клиентом | Нужны события новой доверенной сессии на project-local импорте | Текущий комплект 11/12 отдельно не проверен, `unable_to_verify` |
| Поведение | Нужны реальные routing/workflow, file events, браузер/возобновление | Исторические 38 и current synthetic T01–T08 не названы выполненными; `unable_to_verify` |
| Эффективность | Нужны сопоставимые baseline/target, время/токены и одинаковые условия | Сравнение не выполнено, улучшение не установлено |

Исторический отчёт macOS/CLI, 30 tests, попытка W01, диагностика SQLite/app-server и состав старых снимков имеют единственный подробный источник — [история evals](../evals/README.md). Это результаты 2026-09-05, а не текущий запуск или заранее известная причина новой ошибки. Новая модельная попытка здесь не выполнялась. Минимальная Python 3.11, другие ОС, эффективные permissions, изоляция глобальных дублей, adoption модельной таблицы и поведение текущего quality_owner остаются непроверенными.

## План проверки v5 после исходниковой приёмки

Штатными средствами проверьте: простую правку без подагентов и файлов кампании; широкий запрос с двумя противоречащими уточнениями у `analyst_standard`; Astra только при отдельном прямом пользовательском указании; strict implementation/review с собственными отчётами и envelope; resume без чтения всей истории root; одну quality-партию с браузерным доказательством либо честным `unable_to_verify`.

Для запуска сохраняют только данные, нужные для его воспроизведения и продолжения: клиент, наблюдаемые настройки, входы, действия/артефакты и доступный расход всех ролей; снимок добавляют при точном импорте, переносе между деревьями/сессиями, параллельной записи, выпуске или безопасности. Поведение и применение модели различают. Экономию сравнивают только для одинакового принятого результата: суммарные затраты серии, включая провалы, на число принятых задач; время, токены и качество — отдельно. До отдельного опыта фиксируются бюджет, метрика и практически значимый порог. Эксперимент по эффективности и числовой порог не входят в завершение текстовой корректировки; при неполных счётчиках, нуле принятых задач или недостаточной выборке положительный вердикт эффективности не выдаётся.
