# Совместимость и подключение

Корректный формат, документированное обнаружение, фактическая загрузка и поведение — разные уровни доказательств. Руководства по моделям 6.2 и профилям перечитаны 2026-11-18; историческая проверка CLI-справки датирована 2026-09-06.

## Форматы и документированное обнаружение

Скилл содержит Markdown с YAML frontmatter `name`/`description`; `agents/openai.yaml` задаёт интерфейсные метаданные и политику. В toolkit 12 скиллов: `allow_implicit_invocation: false` у communication и `true` у остальных одиннадцати. Обязательность коммуникации здесь задаёт прямое правило [AGENTS](../AGENTS.md). Список доступных скиллов и чтение выбранной процедуры различаются. Формат и политика описаны в [Build skills](https://learn.chatgpt.com/docs/build-skills).

Руководство обнаружения описывает `.agents/skills` от рабочего каталога до корня Git, пользовательские и системные источники, а также следование symlink для скиллов. Одинаковые имена не сливаются. Поэтому project-local путь надо подтверждать фактически; наличие глобального дубля не подтверждает импорт. [Источник: Where Codex loads local skills](https://learn.chatgpt.com/docs/build-skills).

В toolkit 22 standalone TOML-профиля с `name`, `description`, `developer_instructions`, явными `model`, `model_reasoning_effort` и `sandbox_mode: workspace-write`. Базовый профиль использует имя роли, Terra-варианты — `-terra` в имени файла и `_terra` в `name`, Astra-варианты — `-astra`/`-astra-max` и `_astra`/`_astra_max` соответственно; это те же ответственности. [`developer_astra`](../agents/developer-astra.toml) сохраняет полномочия разработчика и отдельную независимую приёмку. [`reviewer_fast`](../agents/reviewer-fast.toml) проверяет только буквальные несемантические изменения; поведение, смысл, безопасность и межчастевые связи требуют полной ответственности reviewer либо integration_reviewer. Условия автономного выбора Astra и max, приоритет прямых ограничений пользователя и сохранение полномочий заданы в [Model and reasoning selection](../skills/codex-orchestration-pact/SKILL.md#model-and-reasoning-selection). Наличие файла не подтверждает применимость или загрузку. Руководство описывает проектный `.codex/agents/` и пользовательский каталог профилей. [Источник: Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Заданные в custom agent file `model`/`model_reasoning_effort` имеют приоритет. До применения файла клиент разрешает явный spawn, defaults `[agents]`, затем значения родителя; при выборе модели без effort действует уточнение руководства о default effort. Права также зависят от live runtime overrides родителя. Это документированное разрешение настроек, не наблюдение эффективной модели или sandbox текущего комплекта. [Источник: Custom agents; Approvals and sandbox controls](https://learn.chatgpt.com/docs/agent-configuration/subagents).

По текущему [Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents), `sandbox_mode` и approval settings в профиле не заменяют настройки родителя; service tier также наследуется от главной сессии. Запись `workspace-write` в исходнике не даёт права записи сама по себе. Для собственных отчётов нужна разрешённая среда родителя; ограничение предметной записи аналитикам/reviewer остаётся процедурным. Toolkit не поставляет Python-валидатор или Python-зависимости.

Активные Sol/Astra-профили закрепляют `gpt-6.2-sol` и `gpt-6.2-astra`. Идентификаторы и доступность в поддерживаемых Codex app/CLI описаны в [Models](https://learn.chatgpt.com/docs/models); доступ конкретного аккаунта, IDE-клиента и сочетания model/effort проверяется отдельно. В 6.2-профилях явно выбраны `medium`, `high` или `max` по [политике](../skills/codex-orchestration-pact/SKILL.md#model-and-reasoning-selection). Для `max` используйте поддерживаемый клиент и доступный уровень в `/model`; наличие TOML не подтверждает загрузку. Общий минимальный номер CLI для обеих 6.2 в прочитанных источниках не установлен. Источники и основания — в [проверке 2026-11-18](sources.md#astra-и-sol-62--2026-11-18).

Профили не закрепляют ускоренный service tier или увеличенное окно контекста: это отдельные настройки с условиями доступа и расхода. [Models](https://learn.chatgpt.com/docs/models) указывает разные стандартные окна Codex для Astra и Sol; API-предел не следует переносить на клиента автоматически. Предупреждение [миграции API](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra) о потере reasoning при изменении предыдущих сообщений не доказывает поведение конкретной Codex-сессии. Toolkit не добавляет API-параметры или средства управления кешем. Установка, загрузка обновлённых профилей и сравнительные запуски не выполнялись; экономия остаётся неподтверждённой.

Три дополнительных [Terra-профиля](../README.md) явно задают `gpt-6.1-terra` / `medium`; условия их ограниченного применения принадлежат [политике выбора](../skills/codex-orchestration-pact/SKILL.md#model-and-reasoning-selection). По [Models](https://learn.chatgpt.com/docs/models), прочитанному 2026-10-28, для Terra требуется Codex CLI 0.159.0+. Это требование документации, а не проверка установленной версии или доступности аккаунта. `medium` поддерживается по [API model page](https://developers.openai.com/api/docs/models/gpt-6.1-terra); настройки API и загрузка профиля клиентом проверяются раздельно. Смена модели главной сессии не меняет закреплённые model/effort в custom agent file. Новые профили в клиенте не запускались; загрузка, поведение и экономия остаются `unable_to_verify`. Ранее проверенный CLI 0.152.0 не подтверждает поддержку Terra. Источники и границы — в [sources](sources.md#terra--2026-10-28).

При диспетчеризации запрашивайте для root только процессные метаданные и ссылки, сохраняя предметные материалы доступными субагентам. Для ранее загруженного контекста и автоматической доставки полного результата действует правило продолжения из [инварианта диспетчера](../skills/codex-orchestration-pact/SKILL.md#dispatcher-invariant). Инструкция сама по себе не отключает такое поведение клиента и не гарантирует техническую изоляцию контекста. Поведение обновлённого правила в действующем клиенте не проверено.

[Параллельная работа](../skills/codex-orchestration-pact/references/parallel-execution.md) использует доступные клиенту слоты, native-завершение и существующие ролевые артефакты. Политика не увеличивает технические лимиты клиента и не реализует отдельный scheduler. Новые списки переходов в envelope/state читают старый одиночный next_transition по правилам миграции; потребитель должен поддержать очередь и корреляцию ресурсов/результатов для параллельного исполнения. Фактическая загрузка, поведение очереди и ускорение изменённых инструкций в клиенте не проверялись.

## Подключение и параметры клиента

Канонические `skills/` и `agents/` сами ничего не регистрируют. Полная процедура копирования, транзитивные зависимости и адаптация ссылок профилей — в [project-local](project-local.md). Документированная поддержка skill symlink не доказывает поддержку ссылок на профили. Windows junction сохраняется как исторически возможный вариант, без текущей проверки на Windows. Существующая установка и старая пользовательская регистрация автоматически не изменяются.

2026-09-06 локально выполнены только `codex --version` и `codex exec --help` (оба exit 0): `codex-cli 0.152.0`. Справка содержит `--json`, `--cd`, `--sandbox`, `--ephemeral`, `--ignore-user-config`, `--model`, `--output-last-message`. Предупреждение о невозможности создать PATH aliases не помешало справке; оно не является установленной причиной будущего сбоя модели.

По [журналу ChatGPT и Codex](https://learn.chatgpt.com/docs/changelog) от 2026-09-23 каталог Codex CLI 0.156.1 включает GPT-6 Sol и Luna. Их фактическая доступность зависит от клиента и учётной записи; установленную у пользователя версию и загрузку профилей эта запись не подтверждает.

По этой справке `--ignore-user-config` отключает пользовательский config; это не доказательство отключения всех глобальных skills. Проверка версии/справки не запускает модель и не подтверждает доступность ID. Перед применением другого зависящего от версии параметра перечитайте соответствующий официальный раздел и локальную справку.

## Статусы доказательств

| Уровень | Что подтверждает | Текущее ограничение |
|---|---|---|
| Исходники/структура | Ссылки и manifest конкретного снимка | Итоговые результаты сохраняет отчёт приёмки этого снимка; один parser не проверяет смысл |
| Смысловая приёмка | Независимое чтение ролей, зависимостей и прав | Не тождественна запуску клиента |
| Документация и CLI help | Руководства 6.2/профилей прочитаны 2026-11-18; CLI-справка исторически проверена 2026-09-06 | Не подтверждают применение настроек |
| Загрузка клиентом | Нужны события новой доверенной сессии на project-local импорте | Текущий комплект 12/22 отдельно не проверен, `unable_to_verify` |
| Поведение | Нужны наблюдаемые результаты в применимом клиенте или приложении | Формат исходников сам по себе поведение не подтверждает |
