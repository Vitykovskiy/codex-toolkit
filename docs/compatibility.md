# Совместимость и подключение

Корректный формат, документированное обнаружение, фактическая загрузка и поведение — разные уровни доказательств. Проверка руководств и CLI-справки датирована 2026-09-06; отдельная проверка исходников памяти — 2026-10-26. Они не меняют даты исторических тестов.

## Форматы и документированное обнаружение

Скилл содержит Markdown с YAML frontmatter `name`/`description`; `agents/openai.yaml` задаёт интерфейсные метаданные и политику. В toolkit 11 скиллов: `allow_implicit_invocation: false` у communication и `true` у остальных десяти. Обязательность коммуникации здесь задаёт прямое правило [AGENTS](../AGENTS.md). Список доступных скиллов и чтение выбранной процедуры различаются. Формат и политика описаны в [Build skills](https://learn.chatgpt.com/docs/build-skills).

Руководство обнаружения описывает `.agents/skills` от рабочего каталога до корня Git, пользовательские и системные источники, а также следование symlink для скиллов. Одинаковые имена не сливаются. Поэтому project-local путь надо подтверждать фактически; наличие глобального дубля не подтверждает импорт. [Источник: Where Codex loads local skills](https://learn.chatgpt.com/docs/build-skills).

В toolkit 18 standalone TOML-профилей с `name`, `description`, `developer_instructions`, явными `model`, `model_reasoning_effort` и `sandbox_mode: workspace-write`. Базовый профиль использует имя роли, Astra-варианты — суффиксы `-astra`/`-astra-max` в имени файла и `_astra`/`_astra_max` в `name`; это те же ответственности. [`reviewer_fast`](../agents/reviewer-fast.toml) проверяет только буквальные несемантические изменения; поведение, смысл, безопасность и межчастевые связи требуют полной ответственности reviewer либо integration_reviewer. Условия автономного выбора Astra и max, приоритет прямых ограничений пользователя и сохранение полномочий заданы в [Model and reasoning selection](../skills/codex-orchestration-pact/SKILL.md#model-and-reasoning-selection). Наличие файла не подтверждает применимость или загрузку. Руководство описывает проектный `.codex/agents/` и пользовательский каталог профилей. [Источник: Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

Заданные в custom agent file `model`/`model_reasoning_effort` имеют приоритет. До применения файла клиент разрешает явный spawn, defaults `[agents]`, затем значения родителя; при выборе модели без effort действует уточнение руководства о default effort. Права также зависят от live runtime overrides родителя. Это документированное разрешение настроек, не наблюдение эффективной модели или sandbox текущего комплекта. [Источник: Custom agents; Approvals and sandbox controls](https://learn.chatgpt.com/docs/agent-configuration/subagents).

`workspace-write` нужен собственным отчётам; запрет предметной записи аналитикам/reviewer остаётся процедурным. Он не изолирует write-set технически. Toolkit не поставляет Python-валидатор или Python-зависимости.

По документации, собранной скаутом 2026-10-11, GPT-6 Astra поддерживает `max`; доступность конкретного model/effort зависит от клиента и аккаунта. Новые max-профили закрепляют effort явно, сохраняя ответственность базового варианта. Поддержка формата, заданные настройки, фактическая загрузка и наблюдаемое поведение проверяются раздельно. Исходная правка не меняет действующие инструкции установленного клиента и не доказывает расход подписки или экономию. Происхождение этой проверки документов — в [sources](sources.md#astra-подписка-и-intent--2026-10-11); runtime-запуск профилей не выполнялся.

При диспетчеризации клиент должен доставлять root только процессные метаданные и ссылки, сохраняя предметные материалы доступными субагентам. Автоматическая загрузка полного результата в контекст root несовместима с [инвариантом диспетчера](../skills/codex-orchestration-pact/SKILL.md#dispatcher-invariant); инструкция сама по себе не отключает такое поведение клиента. Результат этого ограничения в действующем клиенте не проверен.

[Параллельная работа](../skills/codex-orchestration-pact/references/parallel-execution.md) использует доступные клиенту слоты, native-завершение и существующие ролевые артефакты. Политика не увеличивает технические лимиты клиента и не реализует отдельный scheduler. Новые списки переходов в envelope/state читают старый одиночный next_transition по правилам миграции; потребитель должен поддержать очередь и корреляцию ресурсов/результатов для параллельного исполнения. Фактическая загрузка, поведение очереди и ускорение изменённых инструкций в клиенте не проверялись.

## Встроенная память Codex

Политика использования и граница диспетчера находятся в [Native memory](../skills/codex-orchestration-pact/SKILL.md#native-memory). Ниже — факты реализации **Codex CLI 0.164.0**, прочитанные 2026-10-26 на commit [`6aaac694`](https://github.com/openai/codex/commit/6aaac694803004a63c6f393d153c96d22521a6b9), на который указывает [тег релиза](https://github.com/openai/codex/releases/tag/rust-v0.164.0). Настройки и поведение установленного у пользователя клиента не проверялись.

В этом снимке feature `memories` выключена по умолчанию. Для подстановки памяти также требуется `memories.use_memories`; сводка `memory_summary.md` читается из выбранного каталога Codex home и добавляется в developer context автоматически, без открытия агентом `MEMORY.md`. Фоновая обработка запускается асинхронно и может быть пропущена; память не гарантирует сохранение последнего действия. Источники: [feature](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/features/src/lib.rs), [контекст](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/ext/memories/src/extension.rs#L45-L102), [чтение сводки](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/ext/memories/src/prompts.rs#L31-L63), [фоновый запуск](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/memories/write/src/start.rs#L20-L98).

Для новой диспетчерской сессии этого CLI практический способ отключить штатную память — `codex --disable memories`, эквивалент `codex -c features.memories=false`. Параметр отключает её подстановку и фоновый запуск в этом процессе. Это указание по запуску, а не выполненное изменение конфигурации. Источники: [CLI feature toggles](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/cli/src/main.rs#L963-L998), контекст и фоновый запуск выше.

Учитывайте ограничения:

- Подагенты наследуют конфигурацию родителя. Ролевые overrides допускают отключение memory feature, но не её включение поверх отключения родителя; произвольная секция `[memories]` роли не применяется этим механизмом. Поэтому правка `agents/*.toml` сама по себе не обеспечивает схему «диспетчеру выключено, исполнителям включено». Источники: [child config](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/core/src/agent/child_config.rs#L132-L164), [role overrides](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/core/src/agent/role.rs#L36-L103).
- Отключение не очищает уже загруженную историю. Интерфейс относит изменение Use memories к следующему thread; возобновление старого диалога или полный fork его истории не подтверждает чистоту контекста. Источник: [memory settings](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/tui/src/bottom_pane/memories_settings_view.rs#L81-L98). Новая сессия нужна с разрешёнными исходными ссылками и компактным процессным state, без предметной истории.
- Отключение памяти устраняет только этот канал. Автоматическая доставка предметных результатов подагентов и другие источники контекста отдельно должны соответствовать инварианту диспетчера. Ни инструкция toolkit, ни свежий контекст сами по себе не доказывают техническую изоляцию клиента.

В реализации есть пространства `memories` (v1) и `memories_v2` (v2); v1 — исходное значение enum. Конкретный `MEMORY.md` не является обязательным интерфейсом toolkit. Источник: [MemoryVersion](https://github.com/openai/codex/blob/6aaac694803004a63c6f393d153c96d22521a6b9/codex-rs/protocol/src/memory_version.rs#L7-L21). Для иной версии перечитайте её официальные источники и доступную локальную справку. Чтение исходников не подтверждает загрузку профилей, эффективность, наследование или изоляцию в действующем клиенте; происхождение проверки — в [sources](sources.md#встроенная-память-codex--2026-10-26).

## Подключение и параметры клиента

Канонические `skills/` и `agents/` сами ничего не регистрируют. Полная процедура копирования, транзитивные зависимости и адаптация ссылок профилей — в [project-local](project-local.md). Документированная поддержка skill symlink не доказывает поддержку ссылок на профили. Windows junction сохраняется как исторически возможный вариант, без текущей проверки на Windows. Существующая установка и старая пользовательская регистрация автоматически не изменяются.

2026-09-06 локально выполнены только `codex --version` и `codex exec --help` (оба exit 0): `codex-cli 0.152.0`. Справка содержит `--json`, `--cd`, `--sandbox`, `--ephemeral`, `--ignore-user-config`, `--model`, `--output-last-message`. Предупреждение о невозможности создать PATH aliases не помешало справке; оно не является установленной причиной будущего сбоя модели.

По [журналу ChatGPT и Codex](https://learn.chatgpt.com/docs/changelog) от 2026-09-23 каталог Codex CLI 0.156.1 включает GPT-6 Sol и Luna. Их фактическая доступность зависит от клиента и учётной записи; установленную у пользователя версию и загрузку профилей эта запись не подтверждает.

По этой справке `--ignore-user-config` отключает пользовательский config; это не доказательство отключения всех глобальных skills. Проверка версии/справки не запускает модель и не подтверждает доступность ID. Перед применением другого зависящего от версии параметра перечитайте соответствующий официальный раздел и локальную справку.

## Статусы доказательств

| Уровень | Что подтверждает | Текущее ограничение |
|---|---|---|
| Исходники/структура | Ссылки и manifest конкретного снимка | Итоговые результаты сохраняет отчёт приёмки этого снимка; один parser не проверяет смысл |
| Смысловая приёмка | Независимое чтение ролей, зависимостей и прав | Не тождественна запуску клиента |

| Загрузка клиентом | Нужны события новой доверенной сессии на project-local импорте | Текущий комплект 11/18 отдельно не проверен, `unable_to_verify` |
| Поведение | Нужны наблюдаемые результаты в применимом клиенте или приложении | Формат исходников сам по себе поведение не подтверждает |
