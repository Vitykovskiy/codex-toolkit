# Create a handoff

Root creates a compact process handoff only for an active strict workflow that must continue in another session. Preserve one current state, the literal request/goal references, current assignment IDs/attempts and launch revisions, native handles, accepted report paths and snapshots, pending transitions with dependency gates, resource reservations, blockers, and known cost increments. Keep full subject reports at their artifact paths; root reads no subject artifact, excerpt or summary. Copy only process fields and unchanged original source references from root's own state under the [dispatcher invariant](../../SKILL.md#dispatcher-invariant); subject snapshot/manifests stay referenced. Use the existing state fields from [Parallel execution](../parallel-execution.md), without creating another queue or budget agreement.

The handoff records facts and unknowns, never a new technical decision. A stale report, unsafe path, unknown runtime sender, or missing required capability is a checkpoint with the exact limitation. Do not call accepted work incomplete just to recreate it.

Identify the one current state by path, its recorded plan/route revision and `checkpoint`. Link to its live statuses, assignments, queue and reservations instead of maintaining them again in the handoff. Other handoff fields are references or observations bound to that checkpoint, not another editable state. On another machine where the current state is unavailable, carry an immutable state snapshot with its original path, revision and checkpoint; designate one current state before resuming updates and reconcile native processes before launching work. Do not run two mutable copies. Follow the central [native memory policy](../../SKILL.md#native-memory): memory cannot replace the state or checkpoint, and disabling it does not clear an inherited context.
