# Resume orchestration

Root resumes its own compact strict state after checking process identities, safe path metadata and the permitted routing descriptor. It does not open subject files, assignments, reports or another agent's handoff; the resumed subject owner checks source revision and required artifact contents. Continue the first incomplete action with its existing assignment and accepted evidence. Do not recreate approved work, launch a duplicate event, or turn root into a technical fallback.

If a required role, report, telemetry, or safe transition is unavailable, preserve an exact blocker and wait for the smallest subject-owner action. Unknown cost or coverage remains `unknown`; it is not made zero on resume.

Bound Astra work by responsibility under [Model and reasoning selection](../../SKILL.md#model-and-reasoning-selection). Preserve original messages and ordered corrections, assignments, current evidence, acceptance and the first incomplete action in existing artifacts. Each replacement owner reads the authoritative sources and relevant dependencies, rechecks changed inputs and resumes without repeating accepted unchanged work. File existence alone does not establish current evidence or that it was read. An API context specification proves neither effective subscribed-client context nor perfect memory. Ordinary long work keeps lightweight continuity and does not automatically activate strict state or reports.
