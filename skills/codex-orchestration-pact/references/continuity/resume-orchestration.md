# Resume orchestration

Root resumes its own compact strict state after checking process identities, safe path metadata and permitted routing descriptors. Reconcile active handles with native status before new launches; restore pending transitions, dependency receipts and resource reservations under [Parallel execution](../parallel-execution.md). It does not open subject files, assignments, reports or another agent's handoff; the resumed subject owner checks source revision and required artifact contents. Continue permitted ready work with existing assignments and accepted evidence, without waiting for unrelated branches. Do not recreate approved work, duplicate active assignments or terminal events, or turn root into a technical fallback.

If a required role, report or safe transition is unavailable, preserve an exact blocker for affected work and request the smallest subject-owner action. Unknown cost or coverage remains `unknown`; it is not made zero on resume. Optional usage telemetry and an unset user budget do not block continuation. Preserve explicit limits and cancellation reservations until native termination is confirmed.

Bound Astra work by responsibility under [Model and reasoning selection](../../SKILL.md#model-and-reasoning-selection). Preserve original messages and ordered corrections, assignments, current evidence, acceptance and unfinished work in existing artifacts. Each replacement owner reads the authoritative sources and relevant dependencies, rechecks changed inputs and resumes without repeating accepted unchanged work. File existence alone does not establish current evidence or that it was read. An API context specification proves neither effective subscribed-client context nor perfect memory. Ordinary long work keeps lightweight continuity and does not automatically activate strict state or reports.
