# Orchestration reference

The [portable route table](../SKILL.md#portable-route-table) is authoritative. Existing agent profiles provide model and reasoning settings. This reference does not introduce another sequence of mandatory roles.

The subject owner chooses bounded Astra work and reasoning under [Model and reasoning selection](../SKILL.md#model-and-reasoning-selection), using [Efficiency per accepted task](../SKILL.md#efficiency-per-accepted-task) for the whole cycle under a subscription. Strict root launches the prepared process transition without reading subject material. Profile availability alone does not justify escalation or establish runtime loading.

A ready specification goes to one owner. Ordinary implementation questions stay with the developer. Delegate one material unknown only when the answer is needed to proceed; use the existing analyst or architect responsibility, not an analyst–architect–decomposer relay.

Each subject owner independently finds and reads original user requirements, applicable rules and needed predecessor reports before dependent analysis, design or changes under [Project requirements](../SKILL.md#project-requirements). An existing current set is reused; unknown or scattered rules in orchestrated work can be collected by the existing scout. A simple local owner reads them directly. A ready specification still requires applicable project rules but does not trigger an extra planning role.

A decision owner may prepare responsibility-based assignments and write-sets. An owner selects related implementation, test and documentation work only within the already authorized scope and execution limits. A scope extension needs the appropriate authorization, not an automatic decomposer pass. New auxiliary tooling requires a separate direct user request.

Use one sufficient independent review. Launch the reviewer with unchanged original source references and task/assignment IDs under the [dispatcher invariant](../SKILL.md#dispatcher-invariant); the reviewer checks primary sources and affected-path instructions for omissions as well as the submitted criteria and evidence. It neither implements its own corrections nor approves its own work. Reuse accepted evidence for unchanged parts, and inspect the correction and affected dependencies. Additional review requires a named missing criterion.

Ordinary direct results may remain inline. Dispatched dependency results stay in accessible role-owned artifacts; root receives only process metadata and references. Each role formulates and records its own working task from primary sources; root never reads or restates the task or reports. Formal acceptance preserves the [report contract](templates/report.md). Strict workflows keep role-owned file reports, envelopes, safe state transitions and the first incomplete action on resume. Their details belong to [long orchestration](../../codex-long-orchestration/SKILL.md).
