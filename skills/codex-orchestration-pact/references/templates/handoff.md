# Handoff оркестрации

Передача незавершённой оркестрации сохраняет dispatcher_only и следует [строгому continuity](../../../codex-long-orchestration/references/continuity.md). Здесь только компактные сведения и ссылки; полные отчёты/снимки/история остаются у предметных ролей.

- Task ID и безопасный task_root:
- Goal path (дословная цель):
- State path и route revision:
- Статус снимка: `complete | partial | unstable`
- Время наблюдения / last_checkpoint:
- Constraints path; источник явно заданного лимита, если он есть (отдельный budget path не обязателен):
- Ссылки на дословные исходные сообщения и последующие уточнения; идентификаторы источников и зависимых артефактов для самостоятельного чтения предметной ролью:
- Журнал решений по пути (используй [форму](decision-log.md)):
- Текущие процессные поля envelope в собственном state root и ссылки на артефакты:
- Индекс принятого по пути:
- Git-снимок по каждому обнаруженному контексту: корень, ветка/detached, HEAD, staged/unstaged/untracked, отпечатки рабочего/индексного diff:
- Незавершённые процессы, runtime_handle, фактическое ожидание/остановка и неизвестности:
- Манифесты существенных входов/выходов/новых файлов/удалений по путям:
- Отдельный манифест игнорируемых артефактов по пути:
- Затронутые needs_revalidation и основание владельца:
- Непроверенные критерии, риски и блокеры:
- Очередь разрешённых переходов с зависимостями и ревизиями; завершённые receipts, принятые снимки и резервы ресурсов; точные блокеры затронутых переходов:

Запись атомарная; partial/unstable не объявляются complete. При возобновлении действуют [проектные требования](../../SKILL.md#project-requirements): доступный источник читают до зависимой работы, изменение области или нормы требует проверки затронутой части, включая незакоммиченные изменения. Собственный полный [отчёт](report.md) сохраняет назначенная роль; root не читает его, другие предметные файлы, фрагменты или пересказы. Root возобновляет собственный компактный state, сверяет активные handles до новых запусков и продолжает готовые ветки по [Parallel execution](../parallel-execution.md). Он передаёт исходные ссылки и IDs без переформулирования; новый субагент сам находит материалы, формулирует и фиксирует свою рабочую задачу по [инварианту диспетчера](../../SKILL.md#dispatcher-invariant). Предметную актуальность и влияние изменений проверяет назначенная роль. Незатронутые результаты сохраняются. Новая сессия не считается запущенной по одному наличию handoff.
