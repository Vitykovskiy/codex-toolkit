# Strict dispatcher mode

Apply the [mandatory dispatcher invariant](../../codex-orchestration-pact/SKILL.md#dispatcher-invariant) at every launch, retry, review and resume. Root only dispatches permitted roles and records process metadata. It reads no agent-authored file, assignment, report, excerpt or summary, and neither reformulates the request nor expands or narrows its role. Reading a result for organizational purposes violates the same boundary as subject analysis.

Launch with the role and basic instruction, unchanged original user text or exact reference, task root, assignment ID/attempt and dependency references. The subject owner locates primary sources and required predecessor reports itself, checks their currency, formulates and records its working task, then performs the assigned decision, change or independent review. The working formulation never replaces the original request for the next agent.

A subject owner prepares needed assignment content, graph, write-set and route revision. Root receives only routing fields from the [envelope](templates/envelope.md); the next agent opens the referenced assignment. A ready specification goes directly to its executor. Architect handles material decisions; standalone decomposer remains explicitly requested, not a mandatory relay. Fixes stay with their owner and reviewer. Use integration_reviewer instead of ordinary review only for a named compatibility or security criterion; one sufficient packet review can accept several results.

Root validates envelope shape, runtime sender, assignment ID/attempt, path safety and the permitted transition from process metadata. The reviewer verifies full reports, evidence, source revision and envelope/report correlation. A path-only next transition requires a routing descriptor from its subject owner; root never opens the assignment to infer a role or instruction. Unsafe, ambiguous or stale metadata yields an exact checkpoint.

Before launch root records assignment identity, input revision from available process metadata, permitted transition, shared resource identifiers and known cost state in its own state. Use native completion or blocking waits; duplicate events do not launch twice. Subject owners assess any source or dependency change and return the required revision metadata. After two receipts without confirmed progress, root launches the existing decision owner to prepare a changed strategy; it does not select one itself. Missing delegation, report storage, reference-only delivery or a safe transition stays blocked without a technical or report-reading fallback.
