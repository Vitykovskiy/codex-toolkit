# Strict dispatcher mode

Apply the [mandatory dispatcher invariant](../../codex-orchestration-pact/SKILL.md#dispatcher-invariant) at every launch, retry, review and resume. Root only dispatches permitted roles and records process metadata. It reads no agent-authored file, assignment, report, excerpt or summary, and neither reformulates the request nor expands or narrows its role. Reading a result for organizational purposes violates the same boundary as subject analysis.

Launch with the role and basic instruction, unchanged original user text or exact reference, task root, assignment ID/attempt and dependency references. The subject owner locates primary sources and required predecessor reports itself, checks their currency, formulates and records its working task, then performs the assigned decision, change or independent review. The working formulation never replaces the original request for the next agent.

A subject owner prepares needed assignment content, graph, write-set and route revision. Root receives only routing fields from the [envelope](templates/envelope.md); the next agent opens the referenced assignment. A ready specification goes directly to its executor. Architect handles material technical decisions; decomposer prepares missing execution dependencies and ownership under [Parallel execution](../../codex-orchestration-pact/references/parallel-execution.md), without becoming a mandatory relay. Fixes and implementation integration stay with their developer; independent acceptance stays with the reviewer. Use integration_reviewer instead of ordinary review only for a named compatibility or security criterion; one sufficient packet review can accept several results.

Root validates envelope shape, runtime sender, assignment ID/attempt, revision, path safety and permitted transitions from process metadata. The reviewer verifies full reports, evidence, source revision and envelope/report correlation. A path-only next transition requires a routing descriptor from its subject owner; root never opens the assignment to infer a role or instruction. Unsafe, ambiguous or stale metadata yields an exact checkpoint for affected work; independent ready work may continue.

Root maintains the ready/waiting queue in its existing [state](templates/state.md). Before each launch it records assignment identity, plan/input revision, bound dependency snapshots, resource reservations and known applicable limits, then attaches the native handle. Apply the shared parallel rule for actual capacity, conflicting resources, completion gates and cancellation; no fixed writer cap or mandatory budget agreement is introduced. Use native completion or blocking waits, unlock each successor when its own gates pass, and process duplicate events only once. Subject owners assess source or dependency changes and return affected assignment IDs and revised descriptors; root never computes subject impact.

Apply [Progress and efficiency](../../codex-orchestration-pact/SKILL.md#progress-and-efficiency) at meaningful checkpoints and while work is active. Root displays approximate completion from the current plan owner's aggregate and acts on process signals, including excessive verification, without reading the plan or reports. A signal prompts the existing owner's bounded correction; two receipts without confirmed progress trigger the same route. Preserve required acceptance and delivery stages, current accepted evidence and a changed plan revision. Missing delegation, report storage, reference-only delivery or a safe transition stays blocked without a technical or report-reading fallback.
