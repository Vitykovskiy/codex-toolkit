# Проверка веб-интерфейса

## Когда применять

Применяйте для наблюдения работающего пользовательского сценария, взаимодействия, адаптивности или визуального результата. Доступность проверяйте, только если она прямо включена в задачу и разрешена правилами проекта. Этот навык проверяет результат и не начинает реализацию или исправление приложения.

## Входы и средство

Установите сценарий, источник ожидаемого поведения, среду запуска и допустимые данные. Проверьте, доступны ли приложение, нужный браузер, авторизация и backend. В кампании используйте принятые критерии партии и затронутые состояния/размеры; независимый reviewer наблюдает результат самостоятельно. Эта проверка не назначает владельца кампании и не запускает полный аудит продукта.

Для ручной браузерной проверки агентом используйте глобальный `playwright-cli` как единственный выбор по умолчанию. Он работает headless и с временным профилем по умолчанию; браузер по умолчанию — Google Chrome. Не переключайтесь между CLI, MCP, DevTools и другими средствами по усмотрению агента. Явное требование пользователя или применимое правило проекта о браузере, средстве, профиле и способе проверки имеет приоритет. Интерактивные команды CLI не требуют заранее созданного `*.spec.ts` или Playwright Test. Не создавайте тесты, конфигурацию, скрипты или `.playwright` в проекте ради ручного прохода без отдельного поручения.

Если `playwright-cli`, Chrome, команда запуска, авторизация, backend или необходимые данные недоступны, установите точную причину. Установку CLI выполняйте лишь в рамках полномочий задачи; [официальная инструкция](https://playwright.dev/agent-cli/installation) отделяет CLI, браузер и навык агента. Не объявляйте сценарий пройденным по анализу кода. При отсутствии разрешённого средства, наблюдающего тот же критерий, статус браузерной проверки — `unable_to_verify`; иное средство выбирайте только по явному требованию пользователя или проекта.

## Действия

Запустите приложение по правилам проекта. Откройте нужный URL через `playwright-cli`, получите снимок страницы и выполняйте действия по ссылкам из актуального снимка. После навигации и изменения состояния обновляйте снимок: старые ссылки элементов могут стать недействительными. На каждом существенном шаге сопоставляйте `expected` с реально наблюдаемым `observed`. Проверьте применимые успешный и ошибочный исходы и размеры окна. Не подменяйте реальную серверную интеграцию имитацией API.

Просмотрите относящиеся к сценарию сообщения консоли и сетевые запросы; отделяйте подтверждённый сбой сценария от постороннего события. Сохраняйте screenshot для визуального доказательства, а trace — когда он поможет разобрать сбой. Завершите браузерную сессию командой `close`. Команды и формат доказательств приведены в [чек-листе](references/browser-checklist.md); читайте его при браузерном запуске или визуальном сравнении.

## Результат

Верните пройденные, проваленные и недоступные сценарии. Для каждого укажите условия, `expected`, `observed` и фактически полученное доказательство. Если проверка недоступна, назовите отсутствующую предпосылку точно. Не выдумывайте снимки, трассы или результаты.

## Проверка

Визуальное сравнение применяйте только при сопоставимых браузере, размере и данных; показатели производительности приводите только после измерения с указанной методикой.
