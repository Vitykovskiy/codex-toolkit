# Чек-лист браузерной проверки

Читайте этот чек-лист при браузерном сценарии, сборе артефактов или визуальном сравнении. Правила выбора средства и границы задачи находятся в [SKILL.md](../SKILL.md).

## Ручной проход через CLI

Запустите приложение по инструкции проекта и подставьте его URL. CLI запускается headless с временным профилем и Google Chrome по умолчанию. Если проект требует другой браузер или профиль, следуйте его правилу. Команды выполняются последовательно в одной сессии; `eN` берётся из последнего снимка, а не копируется буквально:

```bash
playwright-cli -s=web-check open http://localhost:4200
playwright-cli -s=web-check snapshot
playwright-cli -s=web-check click eN
playwright-cli -s=web-check snapshot
playwright-cli -s=web-check console error
playwright-cli -s=web-check requests
playwright-cli -s=web-check screenshot
playwright-cli -s=web-check close
```

После навигации или изменения страницы прочитайте новый снимок перед следующим действием. Для поля ввода используйте `fill <ref> <text>`, для нужного размера — `resize <width> <height>`. Screenshot сохраняйте, если он нужен для визуального результата; trace начинайте до воспроизведения сбоя (`tracing-start`) и завершайте после (`tracing-stop`). Сверяйте доступные аргументы с `playwright-cli --help <command>` и [официальным справочником](https://playwright.dev/agent-cli/capabilities). Создание Playwright Test/spec для такого прохода не требуется.

## Доказательство сценария

Для каждого сценария зафиксируйте:

- команду или способ запуска, URL, браузер и размер окна, если они известны;
- изолированные тестовые данные и критические шаги;
- `expected` — ожидаемое поведение и источник критерия;
- `observed` — фактическое наблюдение;
- результат: `passed`, `failed` или `unable_to_verify` с точной причиной;
- фактический путь к снимку, трассе или другому созданному артефакту, если он есть.

Не указывайте путь к несуществующему артефакту и не заменяйте наблюдение предположением по коду.

## Применимые проверки

- Пройдите успешный путь и относящийся к нему ошибочный исход.
- Проверьте клавиатуру, порядок и видимость фокуса и доступное имя, только если доступность включена в задачу и разрешена проектом.
- Отдельно отметьте события консоли и сети: связанное с путём событие, подтверждённый дефект или постороннее событие. Постороннее событие само по себе не доказывает дефект сценария.
- Имитация API не доказывает серверную интеграцию.

## Визуальные и измеримые результаты

Визуальное сравнение имеет смысл только при одинаковых или сопоставимых браузере, размере окна и данных. Числа производительности сообщайте только после измерения с указанной методикой, условиями и единицами.

Для кампании указывайте источник принятого expected, проверяемую ревизию/отпечаток и время наблюдения, насколько они доступны. Независимый reviewer собирает собственное наблюдение результата.

Для точной геометрии сохраняйте viewport в CSS-пикселях, DPR, сценарий и данные; размер PNG и имя файла не доказывают CSS viewport. Неизвестные параметры остаются неизвестными, сопоставимость не предполагается.
