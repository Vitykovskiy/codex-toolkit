# Находка кампании

Следующая форма — незаполненный пример, не наблюдение продукта:

```yaml
id: F001
surface: example-surface
scenario: example-scenario
state: error
viewport: null
expected: null
expected_source: null
observed: "Наблюдение заполняется по проверенному источнику"
evidence: []
classification: unknown
severity: null
confidence: low
decision_required: true
recommended_next_role: analyst
```

В реальной записи `id`, `surface`, `scenario`, `state` и `observed` — непустые строки. ID уникален в реестре. Обязательны наблюдение и его происхождение: `evidence` связывает запись с доступным артефактом/источником наблюдения. Пустой список в примере не разрешает выдавать шаблон за реальную находку.

- `classification`: строго `defect | stale_design | missing_decision | unknown`.
- `severity`: строго `blocker | major | minor | null`; важность не заменяет подтверждённость.
- `confidence`: строго `high | medium | low`; уверенность не заменяет тяжесть.
- `expected` и `expected_source`: непустая строка либо `null` при нехватке основания. Источник содержит проверяемую ссылку/идентификатор требования и применимую область/ревизию.
- `viewport`: `null` при неизвестности, иначе объект наблюдаемых `width`, `height` в CSS-пикселях и `dpr` (неизвестный DPR — `null`). Не выводи значения из PNG.
- `decision_required`: boolean; `recommended_next_role`: точное имя подходящей доступной роли принятого маршрута. Рекомендация сама не создаёт назначение и не даёт root права придумать переход.

`classification: defect` допустим только с ненулевыми `expected`, `expected_source` и наблюдаемыми `evidence`, показывающими расхождение с действующим критерием. Без основания сохраняй неизвестность/отсутствующее решение; устаревший дизайн не становится приказом отката функции.

`evidence` — список проверяемых записей происхождения: ссылка на наблюдение/артефакт, сценарий и данные, код либо тест при наличии, время и проверяемая ревизия/отпечаток, насколько они доступны. Неизвестные метрики не заполняются выдуманными значениями; укажи неизвестность и её влияние. Ссылка на код или предположение о CSS сами по себе не доказывают наблюдение или причину. Причинный вывод требует отдельного доказательства. Независимый reviewer собирает своё наблюдение результата по критериям, а не повторяет оценку quality_owner.

Реестр принадлежит одному назначенному quality_owner. Связанные blockers остаются видимыми при смене партии и владельца; история/доказательства сохраняются по ссылкам. Долговременные предпочтения и критерии живут отдельно в [charter](templates/charter.md) и [preferences](templates/preferences.md).
