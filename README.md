# Codex toolkit

## Назначение

Toolkit — канонический набор 11 общих skills (процедур для Codex), 11 предметных ответственностей и 13 готовых профилей. Проект-потребитель выбирает нужные процедуры и хранит свои соглашения в собственном `AGENTS.md`. Подробные правила находятся в скиллах; README служит каталогом.

## Подключение

Каталоги `skills/` и `agents/` хранят исходники. Для обнаружения клиентом их подключают в поддерживаемые каталоги: сведения руководств, переносимые варианты и результаты локальных проверок разделены в [совместимости](docs/compatibility.md). Windows directory junction остаётся возможным существующим подключением; его наличие не доказывает поддержку на другой ОС.

Пример явного применения после подключения:

```text
$codex-documentation-pact Исправь описание команды в README по текущей справке и проверь изменённые ссылки.
```

Пошаговый будущий импорт без глобальной зависимости описан в [project-local](docs/project-local.md). Для проекта можно адаптировать [фрагмент AGENTS.md](skills/codex-orchestration-pact/references/templates/AGENTS.fragment.md). Правила самого toolkit не переносятся в приложение-потребитель.

## Роли и поток

Маршрутизацию определяет [portable route table](skills/codex-orchestration-pact/SKILL.md#portable-route-table): готовую правку выполняет один владелец, профиль выбирается по ответственности, один достаточный независимый review проводится там, где он требуется, а strict-процесс применяется отдельно только при его условиях.

| Роль | Ответственность |
|---|---|
| [scout](agents/scout.toml) | Собирает проверяемые факты без изменения исходников |
| [analyst](agents/analyst.toml) | Обычный аналитик для конкретной неопределённости |
| [analyst_astra](agents/analyst-astra.toml) | Astra-аналитик по прямому применимому указанию пользователя |
| [architect](agents/architect.toml) | Выбирает техническое решение |
| [decomposer](agents/decomposer.toml) | Самостоятельная декомпозиция или импорт старого процесса по прямому запросу |
| [mechanical](agents/mechanical.toml) | Выполняет однозначную механическую правку |
| [developer](agents/developer.toml) | Реализует назначение и целевые проверки |
| [reviewer](agents/reviewer.toml) | Независимо принимает назначение |
| [reviewer_fast](agents/reviewer-fast.toml) | Проверяет только буквальную несемантическую правку |
| [integration_reviewer](agents/integration-reviewer.toml) | Проверяет уникальные межчастевые связи и полноту |
| [quality_owner](agents/quality-owner.toml) | Владеет одной фазой качества и следующей партией, сохраняет состояние |

`analyst_astra`, `architect_astra` и `quality_owner_astra` используют Astra только при дословном прямом применимом указании пользователя для роли и задачи; сложность, retry и наличие профиля не являются разрешением. `analyst`, `architect` и `quality_owner` сохраняют обычный маршрут. Фактические поставляемые значения model/effort находятся в `agents/*.toml`, а условия выбора — в [portable route table](skills/codex-orchestration-pact/SKILL.md#portable-route-table). Для необязательного запуска заранее выбранного чистого диспетчера после подключения toolkit можно использовать `codex -m gpt-5.6-luna -c 'model_reasoning_effort="low"'`. Эта команда не нужна обычному исполнителю, не меняет уже работающую сессию, не устанавливает профили и не меняет глобальный default.

Обычный результат возвращается кратко в чате, если файл не назначен. Формальная или strict-приёмка использует [канонический отчёт](skills/codex-orchestration-pact/references/templates/report.md): `result.accepts` принимает старый одиночный объект или packet со snapshot каждого результата. Выполнение и независимое принятие имеют разные статусы. Обнаруженный относящийся к цели дефект запускает необходимое исправление и проверку исправления, зависимостей и регрессии. Подробный порядок — в [процедуре оркестрации](skills/codex-orchestration-pact/references/complex-task-orchestration.md).

Служебные сообщения и создаваемая агентами внутренняя процессная проза пишутся кратко по-английски; пользовательские результаты — на языке пользователя; точные исходные строки сохраняются. Новое вспомогательное средство создаётся только по отдельному прямому поручению пользователя.

## Необязательная структурная проверка

Существующий валидатор проверяет форматы, локальные ссылки и связи артефактов, включая некорректные пути и несовпадение назначений. Он и его unit-тест — необязательные средства сопровождения: их запускают отдельно, когда конкретная проверка относится к задаче и разрешена её условиями. Это не единая обязательная последовательность.

| Назначение | Команда |
|---|---|
| Проверить структуру выбранного снимка toolkit | `.venv/bin/python tools/validate_toolkit.py --root .` |
| Проверить изменение самого валидатора | `.venv/bin/python -m unittest discover -s tests -p 'test_validate_toolkit.py'` |
| Проверить пробельные ошибки текущего diff | `git diff --check` |

Для Python-команд требуется Python 3.11+ и зависимости из `requirements-dev.txt`; способ подготовки окружения выбирает разработчик. На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`. Это инструкция запуска, а не утверждение об успешном выполнении на Windows. При недоступном Python или зависимости укажите `not_run` либо `unable_to_verify` и причину. Явное пользовательское исключение проверки означает `not_run`; сама инструкция в README его не отменяет. Структурная проверка не заменяет смысловое чтение, загрузку клиентом или наблюдение поведения.

## Документация и границы

- [Project-local](docs/project-local.md): проверенный снимок, зависимости и проектные расширения.
- [Совместимость](docs/compatibility.md): форматы, обнаружение, проверенная среда и неизвестное.
- [Карта рефакторинга](docs/refactoring-map.md): происхождение и проверка изменений правил.
- [Источники](docs/sources.md): фактически прочитанные разделы и даты.
- Существующий `backup/**` сохраняется неизменным; это условная граница, а не ссылка на обязательный каталог.
- Toolkit поставляет исходники навыков и профилей. Упаковка как плагина и изменение глобальной регистрации не входят в его текущий способ подключения.
- Commit, push, PR и публикация требуют отдельного разрешения.
