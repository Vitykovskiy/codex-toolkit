# Codex toolkit

## Назначение

Toolkit — канонический набор общих skills (инструкций для Codex) и профилей пользовательских ролей. Он отделяет общие правила работы от правил конкретного репозитория: проект выбирает нужные skills по имени и хранит свои уточнения в `AGENTS.md`.

Полный текст пактов находится в соответствующих skills; этот README только помогает найти и подключить их.

## Подключение

Глобальные каталоги skills и ролей подключаются к этому репозиторию через directory junction — ссылку Windows на каталог. Поэтому рабочие репозитории не зависят от расположения toolkit на конкретном компьютере.

В `AGENTS.md` указывают имена skills, например `codex-development-pact`, а не пути к их файлам. Пользовательский `config.toml` регистрирует роли относительными путями `agents/*.toml`; после изменения регистрации нужна новая сессия Codex, чтобы она увидела новые профили.

## Роли и поток

Для обычной задачи Codex работает сам. Для сложной или явно делегированной задачи применяют порядок из [пакта оркестрации](skills/codex-orchestration-pact/SKILL.md).

1. `scout` собирает проверяемые внутренние факты: затронутые файлы, зависимости, потребителей, контракты и риски. Он не редактирует файлы.
2. `analyst` — условная роль. Её подключают после принятой разведки, когда нужно истолковать неоднозначные требования, пользовательские сценарии, варианты или актуальную внешнюю практику. `analyst_deep` нужен при высокой неопределённости или цене ошибки.
3. `architect` выбирает границы и технический вариант; `architect_deep` применяют только при высокой цене ошибки.
4. `decomposer` разбивает принятое решение на независимые атомарные назначения с точными наборами разрешённых файлов.
5. Исполнение выполняют `mechanical` для простой однозначной правки либо `developer` для атомарного назначения. Каждый меняет только свой набор файлов и запускает назначенные проверки.
6. `reviewer` независимо проверяет простую правку; `reviewer_owner` ведёт приёмку целевого или сложного назначения. После сложной задачи `integration_reviewer` проверяет совместимость результата целиком.

Внешнее исследование не заменяет проверку проекта. Его выполняет только `analyst` или `analyst_deep`, только для явно сформулированного исследовательского вопроса и с предпочтением первичных или официальных источников. Ссылку и дату проверки фиксируют в отчёте; недоступный источник отмечают как непроверенный. Остальные роли используют только материалы назначения, указанные источники и собственные файлы.

## Границы

- [backup](backup) — неизменяемое свидетельство; его не редактируют.
- Toolkit не является плагином и не регистрирует роли через Plugin API. Роли подключаются пользовательским `config.toml`.
- Пакты не включают правила отдельного продукта, а переходники не дублируют канонический текст пактов.
- Профили ролей используют только поддерживаемые модели и не заменяют роль или модель молча.
- В toolkit не добавляют постоянные проверяющие сценарии, перехватчики, установочные сценарии или генерируемое рабочее состояние.
- Commit, push и создание PR требуют отдельного разрешения.
